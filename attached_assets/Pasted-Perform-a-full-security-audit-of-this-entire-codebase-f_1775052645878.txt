## 2. BACKEND RATE LIMITING

Check:
- Is express-rate-limit installed and applied to the /api/translate route?
- Is the rate limit set to a maximum of 20 requests per 15 minutes per IP?
- Does it return a proper 429 status code when limit is exceeded?
- Is there a user-friendly error message returned (not a raw error)?

Fix if missing — install and configure like this:
```js
import rateLimit from "express-rate-limit";

const translateLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 20,
  standardHeaders: true,
  legacyHeaders: false,
  message: {
    error: "Even LinkedIn influencers need a break. Try again in a few minutes."
  }
});

app.use("/api/translate", translateLimiter);
```

## 3. INPUT VALIDATION & SANITIZATION

Check every layer:

Frontend:
- Is input checked to be non-empty before sending to backend?
- Is there a 500 character limit enforced in the UI?
- Is there any client-side HTML stripping?

Backend (most important):
- Is input validated as a non-empty string server-side?
- Is input sanitized to strip all HTML and script tags?
- Is the 500 character max enforced server-side independently of frontend?
- Are whitespace-only strings rejected?

Fix if missing — add this validation middleware to the translate route:
```js
import sanitizeHtml from "sanitize-html";

const validateInput = (req, res, next) => {
  let { text } = req.body;

  if (!text || typeof text !== "string") {
    return res.status(400).json({ error: "Invalid input." });
  }

  text = text.trim();

  if (text.length === 0) {
    return res.status(400).json({ error: "Input cannot be empty." });
  }

  if (text.length > 500) {
    return res.status(400).json({ error: "Input must be under 500 characters." });
  }

  // Strip all HTML tags
  req.body.text = sanitizeHtml(text, {
    allowedTags: [],
    allowedAttributes: {}
  });

  next();
};
```

## 6. ERROR HANDLING

Check:
- Are raw error objects or stack traces ever sent to the frontend in 
  any API response?
- Is there a global error handler at the bottom of the Express server?
- Are Groq API errors caught and handled gracefully?
- Do error responses only contain a generic message string, nothing else?

Fix — add this global error handler at the very bottom of index.js 
(after all routes):
```js
app.use((err, req, res, next) => {
  console.error("Server error:", err); // log full error server-side only
  res.status(500).json({ error: "Something went wrong. Please try again." });
});

// Also wrap the translate route logic in try/catch:
try {
  // groq api call here
} catch (err) {
  console.error("Groq API error:", err.message);
  res.status(500).json({ error: "Translation failed. Please try again." });
}
```
